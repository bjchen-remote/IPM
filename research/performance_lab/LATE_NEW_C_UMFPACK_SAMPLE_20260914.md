# 新 C 晚期长跑的只读热点采样（2026-09-14）

R2.2 原始 `t=0` 轨道持续计算至控制台 `τ=3.88000`，物理 `||∇ρ||∞≈197.4`；最近验签 checkpoint 仍为 `τ=3.500136`。R2.6 均摊密度轨道最近验签 `τ=3.800001`，控制台至 `τ=3.85001`，物理梯度约 116.2。两进程均持续占用约一个 CPU 核，没有停止指针或报错；长时间没有新的日志行不足以判定进程挂起。

对两个**正在运行且未中断**的 MATLAB R2026a 进程各做 2 秒 macOS `sample` 只读调用栈采样。在 R2.2 的 1534 个主线程样本中，1358 个位于 `decomp::solve(Umfpack)` / `umfpack_dl_wsolve` 路径（88.5%）；R2.6 为 1557 个样本中的 1315 个（84.5%）。这是特定两秒窗口的栈占比，不是整条轨道的精确时间剖析，亦不能区分单次稀疏求解和该窗口内多次求解。它支持“晚期慢步主要在已有 Poisson 求解路径中耗时”，而非当前样本恰好卡在网格候选规划。

已有 [RHS/LU 研究](FRESH_RHS_COST_AND_LU_SCREEN.md)确认 `ops.poisson` 的 LU 分解已缓存，每个 flow 使用当前状态的一次 Poisson RHS；公开三角缓存路径在小网格不能保持原生解及病态误差，因此不能未经完整数值验收就替换当前 UMFPACK。此次诊断不改活跃进程、冻结发行包、步长门或接受态检查点。后续优化应对同一晚期检查点分离 Poisson solve、Green、输运及每步次数/时钟，再在独立算例验证任何候选；不可由一次采样断言总加速上限。
